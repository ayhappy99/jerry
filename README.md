# Lucky Cabinet

가상 코인으로만 돌아가는 개인용 슬롯머신 웹게임. 서버 없음, 빌드 없음, 실제 금전 요소 없음.

- 심볼은 전부 인라인 SVG, 효과음과 배경음은 WebAudio API로 직접 합성. 외부 이미지·오디오 파일을 쓰지 않는다.
- 외부 리소스는 Google Fonts CSS 하나만 사용한다.
- 상용 슬롯의 상표·로고·타이틀은 쓰지 않는다. 메커니즘만 참고하고 이름과 아트는 전부 창작이다.

## 로컬 실행

ES Module을 쓰기 때문에 `file://`로 열면 CORS로 막힌다. 반드시 HTTP로 띄운다.

```bash
python3 -m http.server 8000
# http://localhost:8000
```

## 화면 흐름

```
[첫 방문] 닉네임 입력 → [로비] → [게임]
[재방문] 로비로 곧장
```

로비에서 게임을 고른다. **코인과 4단 잭팟 풀은 게임끼리 공유**하고, **통계·기록·모드·베팅은 게임별로 따로** 쌓인다.
로비 카드에 게임별 스핀 수·실측 환수율·최고 당첨이 표시되므로 게임마다 밸런스를 따로 확인할 수 있다.
캐비닛 화면 왼쪽 위 `◀` 버튼으로 로비에 돌아간다.

## 소리

효과음과 배경음 모두 WebAudio로 합성한다. **음원 파일을 쓰지 않는 이유는 두 가지다.**
외부 오디오는 핫링크가 끊기면 같이 죽고, 무료 음원도 대부분 CC-BY 같은 저작자 표시 의무가 붙는다.
직접 합성하면 파일 0개, 저작권 리스크 0, 표시 의무 0이다.

| 이벤트 | 소리 |
|---|---|
| 릴 회전 | 대역통과 노이즈 틱 70ms 간격 반복 |
| 릴 정지 | 낮은 트라이앵글(146.8Hz) + 저역 노이즈 |
| 앤티시페이션 | 280Hz → 1500Hz 상승 글리산도 |
| 일반 당첨 | 3음 아르페지오 |
| 빅윈 | 5음 상승 + 피드백 딜레이 잔향 |
| 잭팟 | 8음 팡파르(사각파 + 옥타브 아래 트라이앵글) + 잔향 |
| 카운트업 | 2600Hz 짧은 틱 |
| 버튼 | 아주 짧은 노이즈 클릭 |

배경음은 일렉트로 하우스 루프다. 레퍼런스(윈조이포커·골든카지노) 같은 모바일 카지노 앱이 쓰는 계열이다.

- 진행: **Am - F - C - G** (vi–IV–I–V), **128 BPM**, 16분음표 해상도, 4마디 루프 7.5초
- 편성: 킥(110Hz → 42Hz 스윕 + 클릭), 오프비트 스타카토 소톱니 베이스, 오픈/클로즈 하이햇(하이패스 9kHz),
  플램 2발 클랩, 코드 스탭, 비브라폰풍 아르페지오
- 리듬: 킥 `0,4,8,12` / 클랩 `4,12` / 오픈햇 `2,6,10,14`(하우스의 오프비트) / 베이스 `0,3,6,10,14` / 스탭 `6,14`
- 아르페지오 자리는 마디마다 두 패턴을 번갈아 써서 단조로움을 줄인다
- 40ms 간격 룩어헤드 스케줄러가 0.3초 앞까지 예약하므로 타이밍이 `setInterval` 지터에 흔들리지 않는다
- 각 악기 게인을 낮게 잡아 동시 피크가 0.098이다. 효과음 피크(릴 정지 0.121)보다 낮아 배경으로 깔린다

효과음과 배경음은 별도 게인 버스를 타므로, 빅윈·잭팟 연출 동안 **배경음만 낮췄다가(덕킹)** 복구한다.
탭을 벗어나면 배경음을 멈추고 돌아오면 다시 시작한다.
배경음은 효과음 마스터에 종속된다. 툴바의 소리를 끄면 배경음도 함께 꺼지고 AudioContext 자체를 만들지 않는다.

## 모드와 규칙

| 키 | 표시명 | 릴 | 행 | 라인 | 와일드 | 스캐터 | 잭팟 |
|---|---|---|---|---|---|---|---|
| `classic` | 클래식 3릴 | 3 | 1 | 1 | ✕ | ✕ | ✕ |
| `lines9` | 5릴 9라인 | 5 | 3 | 9 | ○ | ✕ | ✕ |
| `bonus` | 프리스핀·잭팟 | 5 | 3 | 9 | ○ | ○ | ○ |

- 왼쪽 릴부터 연속으로 같은 심볼이 3개 이상이면 당첨. 중간에 끊기면 거기서 종료한다.
- 크라운(와일드)은 스캐터를 뺀 모든 심볼을 대체하고, 대체 시 원래 심볼 배당과 크라운 배당 중 큰 쪽을 적용한다.
  1번 릴에는 와일드를 넣지 않았다.
- 스타(스캐터)는 위치 무관, 개수로만 판정한다. 3개 이상이면 프리스핀 10회. 프리스핀 중 당첨금 2배,
  프리스핀 중 스캐터 3개 이상이면 10회 추가(리트리거).
- 잭팟은 `bonus` 모드에서 한 라인에 **순수 다이아 4개 이상**(와일드 대체 불인정)이면 **픽 보너스**가 열린다.
  타일 9장 중 같은 등급 3개를 모으면 그 등급의 풀 전액을 받고 해당 등급만 seed로 리셋된다.
- 4단 프로그레시브: **GRAND / MAJOR / MINOR / MINI**. 적립분 1%를 50/25/15/10%로 나눠 쌓고,
  픽에서 뽑히는 가중치는 8/16/30/46%다. 적립 비율을 추첨 가중치보다 크게 둔 등급이 더 크게 쌓인다.
- 잭팟 적립은 매 스핀 총 베팅의 1%. 프리스핀은 적립하지 않는다.
- 시작 코인 10,000,000 / 충전 1회 1,000,000 (횟수 제한 없음).

## 설계 원칙

- **결과 확정과 연출은 분리한다.** 스핀 결과는 `rng.drawStops()`가 스핀 시작 시점에 전부 확정하고,
  `reels.js`는 그 결과를 보여주는 일만 한다. 앤티시페이션(스캐터 2개 시 남은 릴 감속)도 확정된
  그리드를 읽어 연출을 고르는 것이며 확률에 개입하지 않는다.
- `engine.js`는 DOM을 참조하지 않는 순수 함수만 둔다. 그래서 밸런스 계산기가 게임과 똑같은
  판정 함수를 그대로 호출할 수 있다.
- 밸런스 수치는 전부 `config.js` 상수다. 다른 파일에 숫자를 하드코딩하지 않는다.
- 예외는 삼키지 않는다. `localStorage` 접근 실패는 그대로 throw 하고, 사용자에게 보여줄 메시지는
  `main.js` 최상단 한 곳에서만 만든다.
- 스핀 1회당 `save()`는 한 번만 호출한다. 잔액·통계는 메모리에서 갱신한다. 자동스핀 중에도 같다.
- `localStorage` 키는 `lucky-cabinet:v1`로 고정하고, 내부 `schema` 필드로 형태 변경을 관리한다.
  버전이 달라도 기존 데이터를 지우지 않고 누락 필드만 기본값으로 채운다. 현재 `schema: 4`
  (2에서 `settings.music`, 3에서 `jackpot.pools` 4단, 4에서 `games[게임키]` 분리).
  v3 이하의 최상위 `stats`·`jackpotHistory`·`bigWins`는 첫 게임 섹션으로 옮겨 보존한다.

## 당첨 연출

결과가 확정된 뒤에만 도는 연출 계층이다. 어느 것도 결과에 개입하지 않는다.

**당첨 확정 순간** (등급에 따라 세기가 달라진다)
- 릴 유리에 섬광 — 일반 당첨 0.4, 빅윈 0.72, 메가윈 0.95, 잭팟 1.0
- 캐비닛 흔들림 — 3 / 7 / 12 / 14px. 이동량을 정수 픽셀로 맞추고 회전을 넣지 않는다.
  소수점 변형은 셀 경계에 합성 이음선을 만든다(실측으로 확인했다).
- 마퀴 전구가 고속 점등으로 바뀌고 릴 프레임이 금색으로 맥동한다

**라인 하이라이트**
- 라인 경로를 `stroke-dashoffset`으로 왼쪽부터 **그려 나간다**
- 당첨되지 않은 셀은 눌러 두고(`opacity .32`, 채도 감소) 당첨 셀만 띄운다
- 당첨 셀에서 링이 한 번 퍼지고(`.burst`), 심볼이 계속 기울며 숨쉰다
- 여러 라인이면 400ms 간격으로 하나씩 → 마지막에 전체를 함께

**등급별 오버레이**
- 빅윈(20배↑): 상단 배너(맥동) + 금화
- 메가윈(100배↑): 풀스크린 + 회전 광선 + 금색 후광 + 5초 카운트업(금액이 박동)
- 잭팟: 전용 풀스크린 + 빠른 광선 + 적색 후광 + `{닉네임}님, 잭팟!` + 확인 버튼
- 프리스핀 발동: 전용 배너(`프리스핀 10회 획득!`)

**금화 파티클**
- 위에서 쏟아지는 비(`coin--rain`)와 아래에서 솟구쳐 흩어지는 분수(`coin--fountain`) 두 종류
- `rotate3d`로 뒤집히며 떨어진다. 이미지가 아니라 라디얼 그라디언트 원이다
- 잭팟·메가윈 오버레이는 열려 있는 동안 2.2초 주기로 다시 쏟는다. 한 파동의 수명(2.4초)에
  맞춰 주기를 잡아 노드가 쌓이지 않는다(실측: 금화 72개·레이어 1개로 유지)

꽝일 때는 이 중 아무것도 하지 않는다.

## 접근성 / 반응형

- 320px 폭에서 가로 스크롤 없이 동작한다. 릴 셀 크기는 `--cell` 변수 하나로 브레이크포인트에서 조정한다.
- `prefers-reduced-motion: reduce`이면 릴을 돌리지 않고 결과를 즉시 표시하고, 당첨 하이라이트는
  점멸 대신 정적 테두리로 보여주며 카운트업을 생략한다.
  섬광·흔들림·금화·광선·후광·링·라인 그리기도 전부 생성하지 않는다(실측: 전 항목 0개).
- 릴 결과는 `role="status"` 라이브 영역이 "체리 4개 라인 2, 1,200,000 코인 획득" 형태로 알린다.
  메시지 줄에는 중복 낭독을 막기 위해 `aria-live`를 두지 않았다.
- 모드 탭은 탭 위젯 표준대로 선택된 탭만 탭 순서에 남고 좌우 화살표로 이동한다.
- 모달은 포커스 트랩·Esc 닫기·포커스 복원을 지원한다.

## 밸런스

목표는 **모드 3종 모두 환수율(RTP) 94~96%**다. 측정 도구는 두 개를 쓴다.

```bash
node tools/rtp.mjs          # 해석적 계산(전수 열거). 몬테카를로 오차가 없다.
node tools/sim.mjs 1000000  # 몬테카를로 교차 검증
```

`tools/rtp.mjs`는 릴 스톱이 균등분포라는 점을 이용해 각 칸의 심볼 확률을 `스트립 내 개수 / 스트립 길이`로
정확히 구하고, 라인 1개의 기대 배당을 전수 열거(최대 8^5 = 32,768가지)한다.
총 베팅 = 라인 베팅 × 9라인이므로 9라인 전체 RTP는 라인 1개의 기대값과 같다.
판정은 `engine.js`의 `evaluateLineSymbols()`를 그대로 호출하므로 게임과 계산기가 어긋날 수 없다.

### 조정 전 (지시서 4-3·4-4의 초기값)

| 모드 | 라인 | 스캐터 | 프리스핀 | 잭팟적립 | 합계 |
|---|---|---|---|---|---|
| classic | 103.31% | — | — | — | **103.31%** |
| lines9 | 85.32% | — | — | — | **85.32%** |
| bonus | 65.57% | 54.92% | 9940.27% | 1.00% | **10061.76%** |

조정이 필요했던 이유는 두 가지다.

**1. bonus 모드의 프리스핀이 발산한다.**
스캐터 가중치 2 / 스트립 길이 29는 스핀당 발동률 **9.76%**다.
프리스핀 1회마다 같은 확률로 10회가 추가되므로 발동 1회당 실제 프리스핀 수는
`10 / (1 - 10 × 0.0976) = 422.5회`가 되고, 여기에 당첨금 2배까지 겹쳐 RTP가 폭발한다.
`10 × 발동률`이 1에 가까워지면 이 재귀가 임계점에 닿기 때문에 발동률을 0.5% 수준까지 내려야 한다.

**2. classic 모드는 지시서 배당표로는 94~96%가 수학적으로 불가능하다.**
RTP는 가중치의 절대값이 아니라 비율에만 의존한다(스트립을 2배로 늘려도 RTP는 같다).
가중치 비율로 RTP를 최소화하는 배치는 `w ∝ pay^(-1/2)`이고, 지시서 배당(10/15/30/60/150/400)에
이를 대입하면 **96.55%**가 나온다. 즉 가중치를 어떻게 바꿔도 96.55% 밑으로 내려갈 수 없다.
그래서 이 모드만 배당을 조정했고, 조정폭이 가장 작은 해(레몬 3개 15 → 12)를 골랐다.
나머지 배당은 지시서 값 그대로다.

### 4단 잭팟과 시드

| 등급 | 시드 | 적립 비율 | 픽 가중치 | 적중 빈도 | 평균 풀 |
|---|---|---|---|---|---|
| GRAND | 30,000,000 | 50% | 8% | 1/158,300 | 약 101,235,000 |
| MAJOR | 8,000,000 | 25% | 16% | 1/79,150 | 약 25,808,750 |
| MINOR | 3,000,000 | 15% | 30% | 1/42,213 | 약 8,698,800 |
| MINI | 1,000,000 | 10% | 46% | 1/27,530 | 약 3,477,739 |

평균 풀 크기는 `적립 비율 ÷ 픽 가중치`에 비례한다. 그래서 GRAND가 MINI의 약 29배로 쌓인다.

**트리거를 다이아 5개에서 4개 이상으로 낮춘 이유.** 단일 잭팟일 때 다이아 5개는 1/234,271이었다.
이를 4단으로 쪼개면 GRAND는 1/2,928,388이 되어 픽 보너스를 사실상 볼 수 없다.
4개 이상으로 낮추면 트리거가 **1/12,664**로 18.5배 잦아진다.
릴 스트립과 배당은 하나도 건드리지 않았으므로 **라인 RTP 84.24%와 합계 94.94%가 그대로다.**

**시드를 낮춘 이유.** 시드는 적중마다 하우스가 새로 얹어주는 프로모션 금액이라 게임 수식에는 들어가지 않지만
실제 지급액에는 포함된다. 그 효과는 `기대 시드 ÷ (적중 주기 × 총 베팅)`이므로 적중이 잦아지면 커진다.
그래서 시드를 30M/8M/3M/1M로 낮췄다. 기본 베팅(90,000) 기준 적중 1회당 기대 시드는 5,040,000이고
시드 효과는 **+0.44%p**, 이를 더한 실효 환수율은 **95.38%**로 목표 범위 안이다.

**픽 순서는 결과를 바꾸지 않는다.** 등급은 스핀 결과와 함께 `rng.drawJackpotTier()`에서 확정되고,
타일은 그 등급만 3장, 나머지 세 등급은 2장씩(3 + 2×3 = 9) 넣어 섞는다.
그래서 당첨 등급 외에는 3개가 모일 수 없고, 어떤 순서로 뒤집어도 같은 등급이 나온다.
업계 표준 방식이고, 이 프로젝트의 "결과 확정과 연출 분리" 원칙과도 일치한다.

### 파라오의 문 (6릴 올웨이즈 캐스케이딩)

캐스케이딩은 연쇄 기대값이 그리드 상태에 의존해 **해석적 계산이 불가능하다.** 그래서 이 게임만
몬테카를로로 측정하고 표준오차를 함께 기록한다.

```bash
node tools/cascade-sim.mjs 2000000
```

**200만 스핀 실측**

| 항목 | 값 |
|---|---|
| 기본 RTP | **94.16%** (표준오차 ±0.32%p, 95% 신뢰구간 93.52 ~ 94.79%) |
| 잭팟 적립 포함 | **95.16%** (목표 94~96%) |
| 시드 효과 포함 실효 | **95.53%** |
| 적중률 | 50.24% (캐비닛 38~42%보다 높다) |
| 프리스핀 발동 | 1/131 |
| 잭팟 트리거(연쇄 7단) | 1/12,270 |
| 연쇄 분포 | 0단 50% · 1단 36% · 2단 11% · 3단 2.8% · 4단 0.7% |

**배당을 역산으로 구한 방법.** 캐스케이딩에서 심볼 제거 여부는 당첨 성립만 보고 배당액은 보지 않는다.
즉 연쇄 구조가 배당값과 무관하므로 **RTP가 배당에 대해 선형**이다.
그래서 (심볼, 개수)별 계수 `C = 스핀 1회당 Σ(ways × 연쇄배수 × 프리배수)`를 실측한 뒤
`RTP = Σ C × 배당`을 목표값에 맞춰 풀었다. 배당을 보기 좋은 값으로 스냅하면 계단 오차가 생기므로
경계 양쪽 중 가까운 쪽을 고르고 개별 배당을 한 칸씩 조정하는 그리디 패스로 마무리했다.
목표 91.48%에 대해 91.50%로 수렴했다.

**심볼을 14종으로 늘린 이유.** 처음 9종으로 만들었을 때 RTP가 3440%였고, 계수를 재 보니
`C6 > C5`였다. 6개 일치가 5개보다 흔하다는 뜻이다. 올웨이즈에서 각 심볼의 릴 출현 확률은
`1-(1-p)^4`이고 `Σp = 1`이라 심볼이 9종이면 가장 흔한 심볼의 `p`가 1/9 밑으로 내려가지 않는다.
그래서 6릴 전체 출현이 5.8%나 됐다. 저배당 석판 타일(10·J·Q·K·A) 5종을 더해 14종으로 만들자
가장 흔한 심볼의 `P(6릴)`이 2.8e-3, 가장 희귀한 심볼이 3.1e-6으로 900배 벌어져
제대로 된 배당 사다리가 가능해졌다.

**잭팟 트리거를 연쇄 7단으로 올린 이유.** 잭팟 풀을 두 게임이 공유하므로 시드 효과도 함께 커진다.
연쇄 5단은 1/488로 너무 잦아 시드 효과가 **+10.33%p**까지 치솟았다.

| 연쇄 | 빈도 | 시드 효과 |
|---|---|---|
| 5단 이상 | 1/488 | +10.33%p |
| 6단 이상 | 1/2,507 | +2.01%p |
| **7단 이상** | **1/13,748** | **+0.37%p** |
| 8단 이상 | 1/46,351 | +0.11%p |

7단이 캐비닛의 잭팟 빈도(1/12,664 · +0.44%p)와 거의 같아 두 게임의 시드 효과가 맞춰진다.
