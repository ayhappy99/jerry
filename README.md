# Lucky Cabinet

가상 코인으로만 돌아가는 개인용 슬롯머신 웹게임. 서버 없음, 빌드 없음, 실제 금전 요소 없음.

- 심볼은 전부 인라인 SVG, 효과음과 배경음은 WebAudio API로 직접 합성. 외부 이미지·오디오 파일을 쓰지 않는다.
- 외부 리소스는 Google Fonts CSS 하나만 사용한다.
- 상용 슬롯의 상표·로고·타이틀은 쓰지 않는다. 메커니즘만 참고하고 이름과 아트는 전부 창작이다.

## 로컬 실행

ES Module을 쓰기 때문에 `file://`로 열면 CORS로 막힌다. 반드시 HTTP로 띄운다.

```bash
python3 -m http.server 8000
# http://localhost:8000
```

## GitHub Pages 배포

1. 이 브랜치를 `main`에 머지한다.
2. Settings → Pages → Build and deployment → Source: **Deploy from a branch**
3. Branch: `main` / `(root)` → Save
4. 루트의 `.nojekyll` 때문에 Jekyll 처리 없이 파일이 그대로 서빙된다.

경로는 전부 상대 경로라서 `user.github.io/<repo>/` 같은 하위 경로에서도 그대로 동작한다.

## 화면 흐름

```
[첫 방문] 닉네임 입력 → [로비] → [게임]
[재방문] 로비로 곧장
```

로비에서 게임을 고른다. **코인은 다섯 게임이 공유**하고, **4단 잭팟 풀은 럭키 캐비닛·파라오의 문이 공유**한다
(복주머니는 자기 풀을 따로 쓰고, 용문·화투는 쌓이는 상금이 아예 없다). **통계·기록·모드·베팅은 게임별로 따로** 쌓인다.
캐비닛 화면 왼쪽 위 `◀` 버튼으로 로비에 돌아간다. 왼쪽에서 오른쪽으로 쓸어도 같다.

## 조작

| 조작 | 동작 |
|---|---|
| SPIN / 스페이스바 | 스핀 1회 |
| 자동 | 횟수 선택 목록(10 / 25 / 50 / 100 / 무한)을 연다 |
| STOP | 자동스핀 중지. 버튼에 남은 횟수가 함께 표시된다 |
| − / ＋ / 최대 | 베팅 단위 변경 (총 베팅 = 단위 × 라인 수 또는 × 10) |
| ← / → | 모드 탭 이동 |
| Tab | 모든 조작 요소 순회 (포커스 링 표시) |
| Esc | 모달 닫기 · 자동 횟수 목록 닫기 |
| 좌 → 우 스와이프 | 열린 것 닫기 → 없으면 이전 화면 |

자동스핀 중에는 SPIN이 비활성되고 STOP만 살아 있다. **프리스핀은 자동 횟수를 소모하지 않는다.**
횟수 목록은 선택·Esc·바깥 클릭 세 가지로 닫힌다.

하단 툴바에서 배당표·기록·소리·충전·설정을 연다. 왼쪽에서 오른쪽으로 밀면 열린 것이 닫히고, 없으면 로비로 돌아간다.
배당표는 **현재 게임·모드 기준으로만** 표시된다. 캐스케이딩 게임에서는 라인 배당표 대신
ways 배당표(심볼 14종 × 3~6개 일치)로 바뀐다.
설정에서 터보 모드, 효과음, 배경음을 각각 켜고 끌 수 있다.

### 하단 통합 조작바

조작 요소를 한 덩어리로 모았다. 실제 캐비닛처럼 시선이 한 곳에 머문다.

```
┌──────────────────────────────────────────┐
│              이번 당첨금                 │  ← 조작바 폭을 가로지르는 띠
│               6,159,000                  │
├───────────────────────────┬──────────────┤
│ 내 코인 16,059,000        │              │
│ 한 번에 거는 돈           │  SPIN  자동  │
│  − 100,000 ＋ 최대        │              │
│  기본 10,000 × 10         │              │
└───────────────────────────┴──────────────┘
```

- **큰 숫자는 한 번 돌릴 때 실제로 빠지는 총액이다.** 단위 베팅은 아래 계산식 줄에만 둔다.
  처음에는 큰 숫자가 단위 베팅이어서 "왜 10배가 빠지냐"는 오해를 만들었다.
  계산은 `totalBet = 라인당 × 라인 수`(캐비닛) / `기본 × 10`(파라오)으로 처음부터 같았고,
  틀린 것은 표시였다.
- 이번 당첨금 숫자 크기는 띠 폭 기준(`container-type: inline-size` + `min(2.4rem, 12cqi)`)으로
  잡아서 잭팟 8자리든 10자리든 잘리지 않는다. 자릿수를 JS로 재지 않는다.
- 꽝이면 숫자만 0으로 바뀌고 발광·맥동은 붙지 않는다.
- 560px 이하에서는 띠 / 코인·베팅 / 버튼 3단으로 쌓인다.

### 가로 화면

기기를 눕히면(`@media (orientation: landscape) and (max-height: 620px)`) 좌우 2단으로 바뀐다.
데스크톱은 높이가 620px을 넘으므로 세로 배치를 그대로 쓴다.

```
┌─────────────────────────────────────────────────┐
│ ◀   LUCKY CABINET  파라오의 문 · 홍길동님의 자리  ☰ │
├──────────────────────────────┬──────────────────┤
│ GRAND  MAJOR  MINOR  MINI    │  이번 당첨금     │
│ ┌──────────────────────────┐ │  내 코인         │
│ │        릴 윈도우         │ │  한 번에 거는 돈 │
│ └──────────────────────────┘ │  SPIN     자동   │
└──────────────────────────────┴──────────────────┘
```

- 하단 툴바 7개는 숨기고 마퀴의 `☰` 메뉴 하나로 들어간다. 세로에서는 툴바를 그대로 쓴다.
- **릴 셀 크기는 고정값이 아니라 남은 높이를 행 수로 나눠 계산한다.**
  `min(상한, (100dvh − 화면요소합) / 행수, (100vw − 조작칸) / 릴수)`
  높이 구간별 고정값(84/68/56/50/42px)으로 잡았을 때는 구간 안에서 남는 높이를 못 써서
  릴이 화면의 절반만 차지했다. 900 × 415에서 캐비닛 56 → 80px, 파라오 44 → 67px로 커졌다.
- 아낄 수 있는 높이는 전부 릴로 보냈다. 잭팟 바는 등급 이름만 남겨 72 → 40px,
  릴 프레임 테두리는 44 → 28px로 줄였다.
- 높이 400px 이하에서는 **릴이 아니라 조작바가 병목**이다(고유 높이 310px).
  740 × 360에서 11px이 넘쳤던 원인이 이것이고, 조작바 내부 여백과 글자를 줄여 258px로 맞췄다.

### 게임 방법 안내

첫 게임 진입 시 한 번 자동으로 뜨는 10단계 안내다. 메뉴 → 게임 방법으로 언제든 다시 본다.

- 실제 화면 요소에 구멍을 뚫어(거대한 `box-shadow`) 하나씩 짚는다. 설명 그림이 아니라 실제 화면이다.
- 4단계는 `＋`를, 5단계는 `SPIN`을 **직접 눌러야** 넘어간다. 5단계는 돌리기 연출이 끝날 때까지
  기다린다(`game.loopPromise`).
- 직접 누르는 단계는 `.tour--pass`로 오버레이가 클릭을 통과시킨다. 나머지 단계는 막는다.
- 한 번 끝내면 `player.tourDoneAt`에 남기고 다시 띄우지 않는다.

### 어트랙트 모드

30초 동안 아무 조작이 없으면 실제 캐비닛처럼 혼자 돌며 손님을 부른다.

- **데모일 뿐이다.** 코인을 건드리지 않고 판정도 하지 않는다. 통계와 저장도 없다.
  `runAttract()`는 스톱만 뽑아 `spinReels`를 재생하며, 오디오 콜백을 넘기지 않으므로 소리도 없다.
- 아무 조작(`pointerdown` / `keydown` / `wheel`)이 있으면 즉시 멈추고 실제 화면으로 돌아온다.
- 모달, 안내, 잭팟 뽑기가 열려 있거나 자동스핀·프리스핀 중이면 시작하지 않는다.

### 프리스핀 전용 화면

프리스핀에 들어가면 다른 세계에 온 신호를 화면과 소리로 함께 준다.

- 목재가 짙어지고 황동이 붉게 바뀐다(`[data-free="true"]`에서 팔레트 변수만 재정의).
  릴 윈도우 배경과 마퀴 발광, 프레임 후광도 함께 붉어진다.
- 배경음이 단조 진행(`FREE_PROGRESSION`)으로 갈아타고 킥과 스탭이 한 칸씩 촘촘해진다.
- 남은 개수 변경은 전부 `setFreeSpins()`를 지난다. 화면 전환을 놓치지 않게 하려는 것이다.

## 소리

효과음과 배경음 모두 WebAudio로 합성한다. **음원 파일을 쓰지 않는 이유는 두 가지다.**
외부 오디오는 핫링크가 끊기면 같이 죽고, 무료 음원도 대부분 CC-BY 같은 저작자 표시 의무가 붙는다.
직접 합성하면 파일 0개, 저작권 리스크 0, 표시 의무 0이다.

**당첨음은 동전이 쏟아지는 소리다.** 동전 1개를 "비정수배 부분음 2개(1 : 2.76) + 스치는 고역 잡음"으로
만들고 수십 개를 겹쳐 쏟아붓는다. 시각을 `진행도^1.7`로 배치해 시작이 촘촘하고 뒤로 갈수록 뜸해진다.
등급이 올라가면 길이와 밀도가 커진다(0.45초 / 24개 → 3.4초 / 42개). 시작에 트레이 울림(98Hz),
전 구간에 깔리는 잡음 층을 노드 1개로 얹는다.

**홀 생활소음**은 효과음·배경음과 별개로 켜고 끈다. 3.2초 브라운 노이즈 한 겹을 반복해
웅성거림을 깔고(노드 1개), 6~15초마다 멀리서 도는 남의 릴, 13~32초마다 멀리서 쏟아지는
남의 동전을 얹는다. 둘 다 고역을 깎아 멀리 있는 소리로 만든다.

| 이벤트 | 소리 |
|---|---|
| 릴 회전 | 대역통과 노이즈 틱 70ms 간격 반복 |
| 릴 정지 | 낮은 트라이앵글(146.8Hz) + 저역 노이즈 |
| 앤티시페이션 | 280Hz → 1500Hz 상승 글리산도 |
| 일반 당첨 | 3음 아르페지오 |
| 빅윈 | 5음 상승 + 피드백 딜레이 잔향 |
| 잭팟 | 8음 팡파르(사각파 + 옥타브 아래 트라이앵글) + 잔향 |
| 카운트업 | 2600Hz 짧은 틱 |
| 버튼 | 아주 짧은 노이즈 클릭 |

배경음은 일렉트로 하우스 루프다. 레퍼런스(윈조이포커·골든카지노) 같은 모바일 카지노 앱이 쓰는 계열이다.

- 진행: **Am - F - C - G** (vi–IV–I–V), **128 BPM**, 16분음표 해상도, 4마디 루프 7.5초
- 편성: 킥(110Hz → 42Hz 스윕 + 클릭), 오프비트 스타카토 소톱니 베이스, 오픈/클로즈 하이햇(하이패스 9kHz),
  플램 2발 클랩, 코드 스탭, 비브라폰풍 아르페지오
- 리듬: 킥 `0,4,8,12` / 클랩 `4,12` / 오픈햇 `2,6,10,14`(하우스의 오프비트) / 베이스 `0,3,6,10,14` / 스탭 `6,14`
- 아르페지오 자리는 마디마다 두 패턴을 번갈아 써서 단조로움을 줄인다
- 40ms 간격 룩어헤드 스케줄러가 0.3초 앞까지 예약하므로 타이밍이 `setInterval` 지터에 흔들리지 않는다
- 각 악기 게인을 낮게 잡아 동시 피크가 0.098이다. 효과음 피크(릴 정지 0.121)보다 낮아 배경으로 깔린다

효과음과 배경음은 별도 게인 버스를 타므로, 빅윈·잭팟 연출 동안 **배경음만 낮췄다가(덕킹)** 복구한다.
탭을 벗어나면 배경음을 멈추고 돌아오면 다시 시작한다.
배경음은 효과음 마스터에 종속된다. 툴바의 소리를 끄면 배경음도 함께 꺼지고 AudioContext 자체를 만들지 않는다.

## 게임과 규칙

### 럭키 캐비닛 (페이라인)

| 키 | 표시명 | 릴 | 행 | 라인 | 와일드 | 스캐터 | 잭팟 |
|---|---|---|---|---|---|---|---|
| `classic` | 클래식 3릴 | 3 | 1 | 1 | ✕ | ✕ | ✕ |
| `lines9` | 5릴 9라인 | 5 | 3 | 9 | ○ | ✕ | ✕ |
| `bonus` | 프리스핀·잭팟 | 5 | 3 | 9 | ○ | ○ | ○ |

- 왼쪽 릴부터 연속으로 같은 심볼이 3개 이상이면 당첨. 중간에 끊기면 거기서 종료한다.
- 크라운(와일드)은 스캐터를 뺀 모든 심볼을 대체하고, 대체 시 원래 심볼 배당과 크라운 배당 중 큰 쪽을 적용한다.
  1번 릴에는 와일드를 넣지 않았다.
- 스타(스캐터)는 위치 무관, 개수로만 판정한다. 3개 이상이면 프리스핀 10회. 프리스핀 중 당첨금 2배,
  프리스핀 중 스캐터 3개 이상이면 10회 추가(리트리거).
- 잭팟은 `bonus` 모드에서 한 라인에 **순수 다이아 4개 이상**(와일드 대체 불인정)이면 **픽 보너스**가 열린다.
  타일 9장 중 같은 등급 3개를 모으면 그 등급의 풀 전액을 받고 해당 등급만 seed로 리셋된다.
- 4단 프로그레시브: **GRAND / MAJOR / MINOR / MINI**. 적립분 1%를 50/25/15/10%로 나눠 쌓고,
  픽에서 뽑히는 가중치는 8/16/30/46%다. 적립 비율을 추첨 가중치보다 크게 둔 등급이 더 크게 쌓인다.
- 잭팟 적립은 매 스핀 총 베팅의 1%. **프리스핀과 잭팟이 없는 모드는 적립하지 않는다.**
  클래식·9라인에서 적립하면 맞출 수 없는 돈을 내는 셈이 되어 그 모드 환수율이 1%p 낮아진다.
- 시작 코인 10,000,000 / 충전 1회 1,000,000 (횟수 제한 없음).

#### 골드 코인 홀드 앤 스핀 (프리스핀·잭팟 모드)

| 항목 | 값 |
|---|---|
| 트리거 | 골드 코인 **5개 이상** |
| 리스핀 | 3번. 새 코인이 하나라도 붙으면 다시 3번으로 늘어난다 |
| 지급 | 붙은 코인에 적힌 배수(총 베팅 배수)의 합 |
| 전 칸 채움 | 15칸을 다 채우면 **잭팟 뽑기**가 열린다 |
| 실측 | 트리거 1/242 · 진입 평균 5.12개 · 종료 평균 7.78개 · 1회 지급 평균 60.8배 |

- 코인은 **라인 배당이 없다.** `LINE_PAYS`에 없으므로 `engine.js`의 `linePayOf()`가 0을 돌려주고
  왼쪽부터 세는 연속을 끊는다. 즉 코인을 스트립에 넣으면 라인 환수율이 저절로 내려가고,
  그 내려간 몫을 홀드 앤 스핀이 되돌려 받는 구조다. 라인 배당표 숫자는 하나도 바꾸지 않았다.
- 전 칸 채움을 GRAND 직행으로 두지 않은 이유: 공유 풀이 계속 털려 "쌓이는 잭팟"이 무너진다.
  기존 다이아 경로와 같은 픽 보너스를 열면 GRAND는 그 중 8%만 나오므로 실효 빈도가
  1/161,000 × 1/0.08 = 200만 스핀에 한 번꼴로 떨어진다.

### 파라오의 문 (6릴 올웨이즈 캐스케이딩)

| 항목 | 값 |
|---|---|
| 릴 × 행 | 6 × 4 (최대 4,096 ways) |
| 판정 | 올웨이즈 — 왼쪽 릴부터 연속으로 있으면 위치 무관 당첨, ways는 릴별 개수의 곱 |
| 최소 일치 | 3릴 |
| 총 베팅 | 베팅 단위 × 10 |
| 와일드 / 스캐터 | 호루스의 눈 / 오벨리스크 (스캐터 4개 이상 → 프리스핀 10회, 당첨금 2배) |
| 연쇄 배수 | 1 / 2 / 3 / 5 / 8 / 12배 (7단 이상은 12배 유지, 최대 30단) |
| 잭팟 | **연쇄 5단** 도달 시 픽 보너스 (캐비닛과 같은 4단 공유 풀) |
| 부적 게이지 | 연쇄 한 단계마다 한 칸. **12칸이 차면** 호루스의 눈이 격자에 내려앉아 끊긴 연쇄를 잇는다 |

- 당첨된 심볼이 사라지고 위에서 새 심볼이 내려와 다시 판정한다. 당첨이 없을 때까지 반복한다.
- 새 심볼은 릴 스트립을 계속 거슬러 올라가며 가져온다. 물리 릴이 이어서 도는 것과 같은 순서다.
- 심볼마다 독립으로 평가하고 성립한 모든 심볼을 지급한다. 와일드는 여러 심볼의 당첨에 동시에 들어간다.
- **부적 게이지는 스핀을 넘어간다.** 못 딴 스핀도 연쇄가 있었으면 게이지가 남으므로,
  게이지 자체가 다음 스핀의 기대가 된다. 약 16스핀마다 한 번 발동한다.
  게이지 값은 `games.pharaoh.charge`로 저장돼 창을 닫았다 열어도 이어진다.
  발동 여부·와일드가 앉는 자리 모두 `spinCascade` 안에서 스핀 시작 시점에 확정되고,
  연출은 `steps`에 끼워 둔 게이지 단계를 재생만 한다.

### 복주머니 (5x5 덩어리 판정)

| 항목 | 값 |
|---|---|
| 릴 x 행 | 5 x 5 |
| 판정 | 덩어리(클러스터) — 같은 심볼이 **상하좌우로 붙어** 5칸 이상 뭉치면 당첨. 대각선은 붙은 것으로 보지 않는다 |
| 최소 덩어리 | 5칸 |
| 배당 구간 | 5 / 6 / 7 / 8 / 9 / 10 / 12칸+ |
| 총 베팅 | 베팅 단위 x 20 |
| 와일드 | 복주머니 — 어떤 심볼로든 변신해 떨어진 두 덩어리를 하나로 잇는다. 와일드만으로 된 덩어리는 배당하지 않는다 |
| 스캐터·프리스핀 | 없음 |
| 금구슬 | 격자 위에 얹히는 배수 배지. 0개 91% / 1개 8% / 2개 1%, 값은 ×2~×100 |
| 잭팟 | **이 게임만의 별도 4단 풀.** 공유 풀과 섞이지 않는다 |
| 잭팟 적립 | **복주머니 심볼이 나온 개수**가 어느 주머니를 채울지 정한다. 1개 MINI · 2개 MINOR · 3개 MAJOR · 4개 이상 GRAND · 0개면 아무것도 안 쌓인다 |
| 잭팟 방식 | **반드시 터지는(must-hit-by) 천장.** 등급마다 시드~천장 사이 한 점을 미리 뽑아 두고, 풀이 그 점에 닿는 순간 터진다 |
| 천장 | GRAND 6,000만 / MAJOR 1,000만 / MINOR 200만 / MINI 50만 (시드는 모두 천장의 1/5) |
| 평균 주기 | 총 베팅 20만 기준 7,868 / 2,009 / 496 / 146스핀 — **어느 등급이든 106스핀마다 하나** |

- 잭팟은 **뽑기 화면이 없다.** 등급이 적립 시점에 이미 정해지므로, 복주머니가 그대로
  팡 하고 터진다. 화면 미터를 텍스트가 아니라 **복주머니 네 개**로 그렸다.
- 주머니는 **속이 보이지 않는다.** 얼마나 찼는지 알 수 있으면 언제 터질지 짐작이 되고,
  터지는 순간의 놀라움이 사라진다. 그래서 채움 표시도, 임박 표시도 두지 않았다.
  네 개가 늘 같은 속도로 숨쉬듯 움직이므로 어느 것이 임박했는지도 드러나지 않는다.
  화면에 남는 단서는 쌓인 금액 하나뿐이고, 그 금액과 터질 지점의 거리는 숨어 있다.
- **돌릴 때마다 쌓이지 않는다.** 처음에는 총 베팅의 4%를 네 주머니에 비율대로 나눠 담았지만,
  그러면 주머니가 보이지 않는 계량기일 뿐이고 무엇 때문에 올랐는지 알 수 없다.
  이제는 **복주머니 심볼이 화면에 나온 개수**가 어느 주머니를 채울지 정한다. 많이 나오면
  큰 주머니가 채워지고, 하나도 없으면(스핀의 30.5%) 아무 주머니도 움직이지 않는다.
  채워진 주머니는 한 번 밝게 빛나서 어디에 들어갔는지 보인다.
- 개수별 확률(실측 200만 스핀: 1개 37.9% · 2개 21.8% · 3개 7.7% · 4개+ 2.2%)에
  한 번 넣는 배수를 맞춰 **환수율과 터지는 주기를 이전 방식과 같게** 유지했다.
  등급 t의 환수율 = `P(개수) × 배수 × (시드 + 천장) / (천장 − 시드)`이다.
- **자주 터지는 쪽과 많이 주는 쪽은 동시에 가질 수 없다.** 평균 지급은
  `주기 × 그 등급의 환수율 × 총베팅`이므로 환수율을 고정하면 둘이 정확히 반비례한다.
  자주 터지는 쪽을 골라 잭팟 몫을 2.94%에서 6.00%로 올렸고, 그만큼 덩어리 배당이 내려갔다.
- 터질 지점을 `localStorage`에 저장한다. 창을 닫았다 열어도 천장까지의 거리가 유지돼야
  환수율이 계산대로 나온다. 매번 새로 뽑으면 천장이 무한히 멀어질 수 있다.
- **금구슬은 릴 심볼이 아니다.** 릴이 멈춘 뒤 격자 위에 얹히는 배지이고, 그 스핀 당첨 합에
  배수를 곱한다. 심볼로 넣으면 스트립 구성이 바뀌어 덩어리가 생기는 확률까지 흔들리고,
  그러면 덩어리 배당을 처음부터 다시 풀어야 한다. 층으로 두면 덩어리 확률은 그대로이고
  배당을 배수 기대값(1.3515)으로 나누기만 하면 환수율이 정확히 유지된다.
- 구슬이 여러 개면 배수를 **더한다.** 곱하면 ×100 두 개만으로 상한이 터진다.

### 용문 (6릴 가변 높이 + 올웨이즈 + 캐스케이딩)

| 항목 | 값 |
|---|---|
| 릴 × 행 | 6 × **2~7 가변** (최대 7⁶ = 117,649 ways) |
| 높이 분포 | 2행 22% / 3행 26% / 4행 22% / 5행 15% / 6행 10% / 7행 5% |
| 판정 | 올웨이즈 — 파라오와 같고, ways는 릴별 개수의 곱 |
| 최소 일치 | 3릴 |
| 총 베팅 | 베팅 단위 × 20 |
| 와일드 / 스캐터 | 여의주 / 용문 (스캐터 4개 이상 → 프리스핀 10회, 당첨금 2배) |
| 연쇄 배수 | 유료 1 / 2 / 3 / 5 / 8 / 12배 · **프리스핀은 연쇄마다 +1배로 상한 없음** |
| 잭팟 | 없음 |

- **릴 높이가 매 스핀 바뀐다.** 높이는 스핀 시작 시점에 `drawHeights()`로 확정되고
  화면 왼쪽 위 `ways` 숫자가 그 결과를 그대로 보여준다. 낮게 열린 판은 192가지,
  다 열린 판은 117,649가지다. 같은 심볼 배치라도 높이에 따라 당첨금이 수백 배 갈린다.
- 렌더는 CSS 한 줄이 전부다. `.reel`에 인라인 `--rows`를 주면
  `height: calc(var(--cell) * var(--rows))`가 그 릴만 다른 높이로 만든다.
  프레임 높이는 최대 행 수로 고정해 스핀마다 화면이 들썩이지 않게 하고,
  `.reels--ragged`가 릴을 프레임 가운데에 맞춘다.
- **쌓이는 상금을 두지 않았다.** 공유 풀에 넣으면 시드 효과가 환수율에 섞여 배당 역산이
  탁해지고, 자기 풀을 또 만들면 복주머니와 같은 장치가 중복된다. 이 게임의 긴장은
  경로 수와 연쇄 배수가 만든다.
- 저배당 5종(10·J·Q·K·A)은 파라오와 공유한다. 실제 슬롯도 카드 숫자를 저배당으로
  돌려 쓴다. 고배당 6종과 와일드·스캐터만 새로 그렸다(조개·붕어·가재·자라·잉어·용·여의주·용문).
- 1번 릴에는 와일드를 넣지 않는다(`reelWeights: [{ orb: 0 }]`). 왼쪽 릴부터 세는
  올웨이즈에서 1번 릴 와일드 하나는 모든 심볼의 당첨을 동시에 연다.

### 화투 (5릴 2행 족보 판정)

| 항목 | 값 |
|---|---|
| 릴 × 행 | 5 × 2 (카드 10장) |
| 판정 | **족보** — 줄도 위치도 보지 않는다. 깔린 10장을 한 손으로 보고 심볼의 장수를 센다 |
| 심볼 | 13종: 광 5 · 열끗 4 · 띠 3 · 피 1 |
| 총 베팅 | 베팅 단위 × 15 |
| 족보 | 19가지. **성립한 족보는 모두 동시에 지급한다**(고스톱의 점수 계산과 같다) |
| 고(GO) | 이긴 판 다음에 한 단 오른다. 배수 1 / 2 / 3 / 5 / **10배**, 꽝이면 0으로 초기화 |
| 와일드·스캐터·프리스핀·잭팟 | 없다 |

- **카드에 읽는 문법을 넣었다.** 장수를 세는 게임이므로 한 눈에 셀 수 있어야 한다.
  빨간 「광」 배지 = 광, 동물 = 열끗, 가로 띠 = 띠, 아무 표시도 없음 = 피.
  배당표 첫 표가 이 문법을 카드 그림과 함께 보여준다.
- 고도리 석 장(매조·기러기·사슴)은 열끗에도 들어가고, 홍단·청단·초단은 띠에도 들어간다.
  고스톱과 같다. 그래서 `삼광 + 홍단 + 띠 5장`이 한 판에 같이 서는 일이 흔하다.
- **고는 스핀을 넘어간다.** `games.hwatu.go`로 저장돼 창을 닫았다 열어도 이어진다.
  배수는 스핀에 *들어갈 때*의 단계로 곱한다(나가는 값이 아니다) — 정상분포를 닫힌 형태로
  쓸 수 있어 환수율이 정확히 계산된다.
- **적중률이 높아야 고가 산다.** 고 단계가 오르려면 이겨야 하고, 상한까지 가려면 네 번
  연속 이겨야 한다. 적중률 47%에서 4고는 5.06%지만 25%로 떨어지면 0.39%가 되어 장치가
  죽는다. 그래서 피·띠·열끗의 낮은 구간(합쳐 스핀의 25%)을 남겨 두었고, 그 대가로
  작은 족보의 배당이 0.2~0.4배로 작다. **작은 족보는 고를 이어 가는 밑돌**이고,
  돈은 고 배수를 타고 들어온다(환수율의 54%가 고 계수에서 나온다).

## 설계 원칙

- **결과 확정과 연출은 분리한다.** 스핀 결과는 `rng.drawStops()`가 스핀 시작 시점에 전부 확정하고,
  `reels.js`는 그 결과를 보여주는 일만 한다. 앤티시페이션(스캐터 2개 시 남은 릴 감속)도 확정된
  그리드를 읽어 연출을 고르는 것이며 확률에 개입하지 않는다.
- `engine.js`와 `cascade.js`는 DOM을 참조하지 않는 순수 함수만 둔다. 그래서 밸런스 계산기가
  게임과 똑같은 판정 함수를 그대로 호출할 수 있다. 캐스케이딩도 스톱 배열만 받으면 연쇄 전체가
  스핀 시작 시점에 확정되고, 연출은 단계 목록(`steps`)을 순서대로 재생할 뿐이다.
- 밸런스 수치는 전부 `config.js` 상수다. 다른 파일에 숫자를 하드코딩하지 않는다.
- 예외는 삼키지 않는다. `localStorage` 접근 실패는 그대로 throw 하고, 사용자에게 보여줄 메시지는
  `main.js` 최상단 한 곳에서만 만든다.
- 스핀 1회당 `save()`는 한 번만 호출한다. 잔액·통계는 메모리에서 갱신한다. 자동스핀 중에도 같다.
- `localStorage` 키는 `lucky-cabinet:v1`로 고정하고, 내부 `schema` 필드로 형태 변경을 관리한다.
  버전이 달라도 기존 데이터를 지우지 않고 누락 필드만 기본값으로 채운다. 현재 `schema: 7`
  (2에서 `settings.music`, 3에서 `jackpot.pools` 4단, 4에서 `games[게임키]` 분리,
  5에서 `player.tourDoneAt`, 6에서 `settings.ambience`, 7에서 `pouchJackpot`).
  v3 이하의 최상위 `stats`·`jackpotHistory`·`bigWins`는 첫 게임 섹션으로 옮겨 보존한다.

## 당첨 연출

결과가 확정된 뒤에만 도는 연출 계층이다. 어느 것도 결과에 개입하지 않는다.

**당첨 확정 순간** (등급에 따라 세기가 달라진다)
- 릴 유리에 섬광 — 일반 당첨 0.4, 빅윈 0.72, 메가윈 0.95, 잭팟 1.0
- 캐비닛 흔들림 — 3 / 7 / 12 / 14px. 이동량을 정수 픽셀로 맞추고 회전을 넣지 않는다.
  소수점 변형은 셀 경계에 합성 이음선을 만든다(실측으로 확인했다).
- 마퀴 전구가 고속 점등으로 바뀌고 릴 프레임이 금색으로 맥동한다

**라인 하이라이트**
- 라인 경로를 `stroke-dashoffset`으로 왼쪽부터 **그려 나간다**
- 당첨되지 않은 셀은 눌러 두고(`opacity .32`, 채도 감소) 당첨 셀만 띄운다
- 당첨 셀에서 링이 한 번 퍼지고(`.burst`), 심볼이 계속 기울며 숨쉰다
- 여러 라인이면 400ms 간격으로 하나씩 → 마지막에 전체를 함께

**등급별 오버레이**
- 빅윈(20배↑): 상단 배너(맥동) + 금화
- 메가윈(100배↑): 풀스크린 + 회전 광선 + 금색 후광 + 5초 카운트업(금액이 박동)
- 잭팟: 전용 풀스크린 + 빠른 광선 + 적색 후광 + `{닉네임}님, 잭팟!` + 확인 버튼
- 프리스핀 발동: 전용 배너(`프리스핀 10회 획득!`)

**금화 파티클**
- 위에서 쏟아지는 비(`coin--rain`)와 아래에서 솟구쳐 흩어지는 분수(`coin--fountain`) 두 종류
- `rotate3d`로 뒤집히며 떨어진다. 이미지가 아니라 라디얼 그라디언트 원이다
- 잭팟·메가윈 오버레이는 열려 있는 동안 2.2초 주기로 다시 쏟는다. 한 파동의 수명(2.4초)에
  맞춰 주기를 잡아 노드가 쌓이지 않는다(실측: 금화 72개·레이어 1개로 유지)

**캐스케이딩 연출** (파라오의 문)
- 당첨 셀 강조(0.62초) → 폭발하며 축소·소멸(0.26초) → 새 심볼 낙하(0.3초) → 다음 단계
- 낙하 거리는 릴마다 다르다. 그 릴에서 사라진 셀 수만큼 위에서 내려온다.
  와일드는 여러 심볼의 당첨에 동시에 들어가므로 `cascade.js`와 같은 방식으로 중복을 걷어내고 센다
- 단계마다 `연쇄 N단 ×배수 · M ways` 배지를 갱신한다
- 모션 최소화 설정에서는 마지막 그리드만 즉시 표시한다

꽝일 때는 이 중 아무것도 하지 않는다.

상용 슬롯(윈조이포커 등)의 **레이아웃 관습만** 참고했다. 상표·로고·심볼 아트는 쓰지 않았다.

| 하단 통합 조작바 | TOTAL WIN 띠 + 크레딧·베팅 + SPIN/자동 (위 [하단 통합 조작바](#하단-통합-조작바)) |

| 릴 세퍼레이터 | 릴 사이 1px 황동 기둥. 릴이 `overflow: hidden`이므로 셀 좌측 여백 안에 그린다 |

## 접근성 / 반응형

- **확대/축소만 막는다** (`maximum-scale=1, user-scalable=no`). 게임 중 핀치 줌이 들어가면
  가로 화면의 릴 크기 계산이 흔들려 크기가 튄다.
  (확대 금지는 접근성 지침과 상충하는 선택이며, iOS Safari는 `user-scalable=no`를 무시한다)
- **스크롤은 막지 않는다.** 가로 화면에서 문서를 화면 높이에 고정해 봤지만, 그러면 화면이
  낮을 때 릴이 읽을 수 없을 만큼 작아진다. 대신 릴 셀에 `max()`로 바닥을 깔았다
  (캐비닛 64 / 파라오 56 / 복주머니 56px). 한 화면에 들어가면 들어가는 대로 두고,
  안 들어가면 줄이는 대신 페이지가 스크롤된다.
- 가로 화면의 릴 계산은 `dvh`가 아니라 `svh`를 쓴다. 스크롤 중 URL 바가 숨었다 나타나면
  `dvh`가 흔들려 릴 크기가 다시 계산될 때마다 튀지만, `svh`는 URL 바가 보이는 상태로 고정이다.
- 320px 폭에서 가로 스크롤 없이 동작한다. 릴 셀 크기는 `--cell` 변수 하나로 조정한다
  (세로는 브레이크포인트, 가로는 남은 높이 계산식 + 바닥값).
- `prefers-reduced-motion: reduce`이면 릴을 돌리지 않고 결과를 즉시 표시하고, 당첨 하이라이트는
  점멸 대신 정적 테두리로 보여주며 카운트업을 생략한다.
  섬광·흔들림·금화·광선·후광·링·라인 그리기도 전부 생성하지 않는다(실측: 전 항목 0개).
- 릴 결과는 `role="status"` 라이브 영역이 "체리 4개 라인 2, 1,200,000 코인 획득" 형태로 알린다.
  메시지 줄에는 중복 낭독을 막기 위해 `aria-live`를 두지 않았다.
- 모드 탭은 탭 위젯 표준대로 선택된 탭만 탭 순서에 남고 좌우 화살표로 이동한다.
- 모달은 포커스 트랩·Esc 닫기·포커스 복원을 지원한다.
- 자동 횟수 목록은 `role="menu"`로 열리며 첫 항목에 포커스가 가고, Esc로 닫으면 자동 버튼으로
  포커스가 돌아온다. 목록이 열려 있는 동안에는 스페이스바가 스핀으로 가지 않는다.
- STOP 버튼은 남은 횟수를 `aria-label`에도 같이 넣는다(`자동 스핀 중지, 7회 남음`).

## 심볼 아트

전부 인라인 SVG다. 플랫 아이콘처럼 보이지 않게 하는 것은 그림 솜씨가 아니라 **빛 모델링**이다.
처음 만든 심볼이 이모지처럼 보였던 이유는 그라디언트가 2~3스톱이고 단색 실루엣이었기 때문이다.
광원을 왼쪽 위 하나로 고정하고 심볼마다 아래 레이어를 쌓았다.

```
접지 그림자 → 본체(재질 그라디언트) → 면 분할 → 오클루전 → 스페큘러 → 림 라이트
```

**조명 필터를 쓰지 않은 이유.** `feSpecularLighting` 같은 필터가 가장 쉬운 길이지만,
릴이 돌 때 셀이 동시에 150~200개 그려지고 거기에 모션 블러 필터가 이미 걸려 있다.
조명 필터를 심볼마다 얹으면 스핀 프레임이 무너진다. 블러가 필요한 자리는
**투명도로 페이드하는 그라디언트**로 대신했다(필터 비용 0). 실측으로 60fps를 유지한다.

| defs | 역할 |
|---|---|
| `m-shadow` | 접지 그림자. 심볼이 릴 위에 떠 있어 보이게 한다 |
| `m-key` / `m-rim` | 위에서 들어오는 빛 / 아래에서 반사되어 올라오는 빛 (테두리 스트로크) |
| `m-occl` | 빛 반대쪽(오른쪽 아래)이 어두워지는 정도 |
| `m-spec` / `m-sheen` | 에나멜·유리의 좁고 선명한 반사 / 둥근 물체의 넓고 부드러운 반사 |
| `m-gold` | 밝은 띠와 어두운 골을 번갈아 둔 7스톱. 이 밴딩이 금속으로 읽히게 하는 핵심이다 |
| `m-gem-*` | 다이아몬드 면별 밝기 5종 + `m-caustic` + `m-glow-cyan` |

재질마다 처리를 달리했다. 금속은 밴딩, 젬은 면별 밝기 대비, 과일은 구면 + 넓은 광택 +
좁은 스페큘러, 석재는 밝은 면/어두운 면 분할이다.

같은 패스를 여러 겹 쓰는 심볼은 실루엣을 `defs`에 한 번만 두고 `<use>`로 참조한다
(`p-seven`, `p-crown`, `p-star`, `p-bell`, `p-tile`, `p-hood`, `p-nemes`, `p-petal`).
복붙이 없으니 레이어가 어긋날 수 없다.

**형태를 여러 번 고친 것.** 코브라는 정면 후드로 세 번 그렸지만 폭·비율을 어떻게 바꿔도
버섯으로 읽혔다. 옆모습(S자 몸통 + 뒤로 펴진 후드 + 오른쪽을 보는 머리)으로 바꾸고 나서
뱀으로 읽힌다. 연꽃은 꽃잎의 폭:길이가 2.2일 때 잎처럼 보여서 1.6으로 넓혔다.

`tools/symbol-sheet.html`로 확대 160px · 릴 92px · 최소 48px 세 크기를 한 번에 본다.
릴 셀과 같은 배경·크기를 쓰므로 실제 게임에서 보이는 그대로다.

## 밸런스

목표는 **게임 5종 모든 모드에서 환수율(RTP) 105%**다.

원래 목표는 실제 슬롯과 같은 94~96%였다. 그 제약 아래에서는 "자주 터지는 것"과
"많이 주는 것"이 정확히 반비례하기 때문에, 둘을 동시에 올리려면 환수율 자체를 올려야 한다.
사용자가 그쪽을 택했으므로 94~96% 원칙을 버리고 105%로 옮겼다.
가상 코인만 쓰는 개인용 게임이라 실제 금전 손실이 없다는 점이 전제다.
105%는 코인이 아주 천천히 늘어나면서도 개별 스핀의 승패는 그대로 남는 값이다.

이 절의 94~96% 논의는 옮기기 전의 기록이며, 어떤 제약 때문에 어떤 선택을 했는지를
남겨 두기 위해 지우지 않았다. 확정값 표는 105% 기준으로 갱신했다.

측정 도구는 두 개를 쓴다.

```bash
node tools/rtp.mjs          # 해석적 계산(전수 열거). 몬테카를로 오차가 없다.
node tools/sim.mjs 1000000  # 몬테카를로 교차 검증
```

`tools/rtp.mjs`는 릴 스톱이 균등분포라는 점을 이용해 각 칸의 심볼 확률을 `스트립 내 개수 / 스트립 길이`로
정확히 구하고, 라인 1개의 기대 배당을 전수 열거(최대 8^5 = 32,768가지)한다.
총 베팅 = 라인 베팅 × 9라인이므로 9라인 전체 RTP는 라인 1개의 기대값과 같다.
판정은 `engine.js`의 `evaluateLineSymbols()`를 그대로 호출하므로 게임과 계산기가 어긋날 수 없다.

### 조정 전 (지시서 4-3·4-4의 초기값)

| 모드 | 라인 | 스캐터 | 프리스핀 | 잭팟적립 | 합계 |
|---|---|---|---|---|---|
| classic | 103.31% | — | — | — | **103.31%** |
| lines9 | 85.32% | — | — | — | **85.32%** |
| bonus | 65.57% | 54.92% | 9940.27% | 1.00% | **10061.76%** |

조정이 필요했던 이유는 두 가지다.

**1. bonus 모드의 프리스핀이 발산한다.**
스캐터 가중치 2 / 스트립 길이 29는 스핀당 발동률 **9.76%**다.
프리스핀 1회마다 같은 확률로 10회가 추가되므로 발동 1회당 실제 프리스핀 수는
`10 / (1 - 10 × 0.0976) = 422.5회`가 되고, 여기에 당첨금 2배까지 겹쳐 RTP가 폭발한다.
`10 × 발동률`이 1에 가까워지면 이 재귀가 임계점에 닿기 때문에 발동률을 0.5% 수준까지 내려야 한다.

**2. classic 모드는 지시서 배당표로는 94~96%가 수학적으로 불가능했다.**
RTP는 가중치의 절대값이 아니라 비율에만 의존한다(스트립을 2배로 늘려도 RTP는 같다).
가중치 비율로 RTP를 최소화하는 배치는 `w ∝ pay^(-1/2)`이고, 지시서 배당(10/15/30/60/150/400)에
이를 대입하면 **96.55%**가 나온다. 즉 가중치를 어떻게 바꿔도 96.55% 밑으로 내려갈 수 없다.
그래서 이 모드만 배당을 조정했고, 조정폭이 가장 작은 해(레몬 3개 15 → 12)를 골랐다.
나머지 배당은 지시서 값 그대로다.

### 4단 잭팟과 시드

| 등급 | 시드 | 적립 비율 | 픽 가중치 | 적중 빈도 | 평균 풀 |
|---|---|---|---|---|---|
| GRAND | 30,000,000 | 50% | 8% | 1/158,300 | 약 101,235,000 |
| MAJOR | 8,000,000 | 25% | 16% | 1/79,150 | 약 25,808,750 |
| MINOR | 3,000,000 | 15% | 30% | 1/42,213 | 약 8,698,800 |
| MINI | 1,000,000 | 10% | 46% | 1/27,530 | 약 3,477,739 |

평균 풀 크기는 `적립 비율 ÷ 픽 가중치`에 비례한다. 그래서 GRAND가 MINI의 약 29배로 쌓인다.

**트리거를 다이아 5개에서 4개 이상으로 낮춘 이유.** 단일 잭팟일 때 다이아 5개는 1/234,271이었다.
이를 4단으로 쪼개면 GRAND는 1/2,928,388이 되어 픽 보너스를 사실상 볼 수 없다.
4개 이상으로 낮추면 트리거가 **1/12,664**로 18.5배 잦아진다.
릴 스트립과 배당은 하나도 건드리지 않았으므로 **라인 RTP 84.24%와 합계 94.94%가 그대로다.**

**시드를 낮춘 이유.** 시드는 적중마다 하우스가 새로 얹어주는 프로모션 금액이라 게임 수식에는 들어가지 않지만
실제 지급액에는 포함된다. 그 효과는 `기대 시드 ÷ (적중 주기 × 총 베팅)`이므로 적중이 잦아지면 커진다.
그래서 시드를 30M/8M/3M/1M로 낮췄다. 기본 베팅(90,000) 기준 적중 1회당 기대 시드는 5,040,000이고
트리거를 다이아 3개로 낮춘 뒤 시드 효과는 **+1.72%p**다(1/867 × 평균 시드 1,338,000 ÷ 90,000).

**픽 순서는 결과를 바꾸지 않는다.** 등급은 스핀 결과와 함께 `rng.drawJackpotTier()`에서 확정되고,
타일은 그 등급만 3장, 나머지 세 등급은 2장씩(3 + 2×3 = 9) 넣어 섞는다.
그래서 당첨 등급 외에는 3개가 모일 수 없고, 어떤 순서로 뒤집어도 같은 등급이 나온다.
업계 표준 방식이고, 이 프로젝트의 "결과 확정과 연출 분리" 원칙과도 일치한다.

### 골드 코인 홀드 앤 스핀 밸런스

리스핀은 앞선 상태에 의존해 **해석적 계산이 불가능하다.** 그래서 이 기능만 몬테카를로로 재고
표준오차를 함께 기록한다. 판정은 `js/hold.js`와 `js/engine.js`를 그대로 호출한다.

```bash
node tools/hold-sim.mjs              # 코인 가중치별 균형 표
node tools/hold-sim.mjs 3 10000000   # 확정값 상세
```

**1,000만 스핀 실측 (확정값)**

| 항목 | 값 |
|---|---|
| 라인 | 70.14% |
| 스캐터 | 0.93% |
| 프리스핀 | 5.64% (발동 1/262) |
| 잭팟 적립 | 1.00% (다이아 1/867) |
| 홀드 앤 스핀 | **24.73%** (표준오차 ±0.14%p) |
| 시드 효과 | 다이아 1.71% + 전 칸 0.01% |
| **합계** | **104.15%** |
| 적중률 | 33.3% (코인 넣기 전 38~42%) |

**균형점을 찾은 방법.** 코인 가중치를 올리면 라인 환수율이 내려가고(연속을 끊으므로)
홀드 앤 스핀 트리거가 올라간다. 두 효과가 반대로 움직이므로 균형점이 있다. 다만
**트리거가 가중치에 극도로 민감하다** — 15칸 중 5~6개라는 꼬리 사건이라서 정수 가중치
하나 차이로 몇 배씩 뛴다.

| 트리거 | 가중치 | 라인 | 적중률 | 트리거 | 필요 코인 평균 |
|---|---|---|---|---|---|
| 6개 | 3 | 62.9% | 33.3% | 1/2,299 | 62.5배 (사실상 볼 수 없다) |
| 4개 | 3 | 62.9% | 33.4% | 1/41 | 1.2배 (너무 잦다) |
| **5개** | **3** | **62.9%** | **33.3%** | **1/242** | **7.7배** |
| 5개 | 5 | 52.5% | 28.6% | 1/46 | 1.7배 (적중률이 무너진다) |

트리거 5개 · 가중치 3에서 적중률 33%를 지키면서 보너스를 볼 수 있는 빈도가 나왔다.
리스핀 밀도(`cellOdds`)는 모이는 코인 수와 전 칸 채움 빈도를 함께 정하므로, 전 칸이
1/200,000 스핀 근처가 되는 0.05로 잡았다. 마지막으로 코인 값 분포를
`필요 몫 24.78% ÷ 트리거 1/242 ÷ 평균 7.76개 = 7.74배`로 역산해 평균 7.78배로 맞췄다.

### 파라오의 문 밸런스

캐스케이딩은 연쇄 기대값이 그리드 상태에 의존해 **해석적 계산이 불가능하다.** 그래서 이 게임만
몬테카를로로 측정하고 표준오차를 함께 기록한다.

```bash
node tools/cascade-sim.mjs 2000000
```

**300만 스핀 실측**

| 항목 | 값 |
|---|---|
| 기본 RTP | **101.43%** (표준오차 ±0.28%p, 95% 신뢰구간 100.87 ~ 101.98%) |
| 잭팟 적립 포함 | **102.43%** |
| 시드 효과 포함 실효 | **105.44%** (1/445 × 평균 시드 1,338,000 ÷ 100,000 = 3.01%p) |
| 적중률 | 50.15% (캐비닛 38~42%보다 높다) |
| 프리스핀 발동 | 1/130 (리트리거 0.74%) |
| 잭팟 트리거(연쇄 5단) | 1/445 |
| 연쇄 분포 | 0단 50% · 1단 36% · 2단 10% · 3단 2.8% · 4단 0.7% · 5단 0.17% |

**배당을 역산으로 구한 방법.** 캐스케이딩에서 심볼 제거 여부는 당첨 성립만 보고 배당액은 보지 않는다.
즉 연쇄 구조가 배당값과 무관하므로 **RTP가 배당에 대해 선형**이다.
그래서 (심볼, 개수)별 계수 `C = 스핀 1회당 Σ(ways × 연쇄배수 × 프리배수)`를 실측한 뒤
`RTP = Σ C × 배당`을 목표값에 맞춰 풀었다. 배당을 보기 좋은 값으로 스냅하면 계단 오차가 생기므로
경계 양쪽 중 가까운 쪽을 고르고 개별 배당을 한 칸씩 조정하는 그리디 패스로 마무리했다.
사다리 단조성은 세로(같은 심볼의 개수별)와 가로(같은 개수의 심볼별) 둘 다 검사한다.

계수를 재는 스크립트에서 두 가지 편향을 찾아 고쳤다. 둘 다 계수를 낮게 잡아
배당을 과하게 올리게 만든다.
- **프리스핀 리트리거를 빠뜨렸다.** `spinCascade`는 프리스핀 중에도 스캐터가 나오면
  다시 부여하는데, 스크립트가 유료 스핀만 부여하도록 짜여 있었다. 프리스핀 수가 9% 적게
  나와 환수율이 1.3%p 낮게 잡혔다. 독립 시뮬레이터와 1.7%p 어긋난 원인이었다.
- **스캐터 개수를 6에서 잘랐다.** `scatterPays`는 12개까지 있는데 스크립트가 7개 이상을
  6으로 묶어 15배로 계산했다. 실제로는 40~2,000배다.
고친 뒤 계수 기반 추정(101.20%)과 독립 시뮬레이터(101.43% ± 0.28%p)가 1σ 안에서 맞는다.

**심볼을 14종으로 늘린 이유.** 처음 9종으로 만들었을 때 RTP가 3440%였고, 계수를 재 보니
`C6 > C5`였다. 6개 일치가 5개보다 흔하다는 뜻이다. 올웨이즈에서 각 심볼의 릴 출현 확률은
`1-(1-p)^4`이고 `Σp = 1`이라 심볼이 9종이면 가장 흔한 심볼의 `p`가 1/9 밑으로 내려가지 않는다.
그래서 6릴 전체 출현이 5.8%나 됐다. 저배당 석판 타일(10·J·Q·K·A) 5종을 더해 14종으로 만들자
가장 흔한 심볼의 `P(6릴)`이 2.8e-3, 가장 희귀한 심볼이 3.1e-6으로 900배 벌어져
제대로 된 배당 사다리가 가능해졌다.

**잭팟 트리거를 연쇄 5단으로 내린 이유.** 7단은 1/13,748로, 한 자리에 앉아 있는 동안
사실상 볼 수 없었다. 5단이면 1/445다.

| 연쇄 | 빈도 | 시드 3,000만일 때 시드 효과 | 시드 800만일 때 |
|---|---|---|---|
| **5단 이상** | **1/445** | +10.33%p | **+3.01%p** |
| 6단 이상 | 1/2,507 | +2.01%p | +0.53%p |
| 7단 이상 | 1/13,748 | +0.37%p | +0.10%p |

시드 효과는 빈도 x 시드이므로 빈도를 20배 올리면 시드를 그만큼 낮춰야 통제된다.
GRAND 시드를 3,000만에서 800만으로(평균 시드 5,040,000 → 1,338,000) 내려
빈도를 올리고도 시드 효과를 3%p에 묶었다.

**가상의 홀은 없앴다.** 옆 기계들이 함께 적립하는 연출 때문에 손을 놓고 있어도 상금이
계속 올라갔다. 미터가 살아 보이는 대신 "내가 쌓은 돈"이라는 감각이 사라져서,
쌓이는 상금은 내 스핀으로만 움직이게 되돌렸다.

### 복주머니 밸런스

덩어리 판정은 격자 전체 모양에 의존해 전수 열거가 불가능하다(8^25 = 3.8e22). 그래서 덩어리 몫만
몬테카를로로 재고, 잭팟 몫은 해석적으로 정확히 더한다.

```bash
node tools/cluster-sim.mjs 4000000
```

**400만 스핀 실측 (확정값)**

| 항목 | 값 |
|---|---|
| 덩어리 RTP | **98.72%** (표준오차 ±0.11%p) |
| 잭팟 | **6.01%** (심볼 개수 확률만 실측, 나머지는 해석적) |
| 합계 | **104.72%** |
| 적중률 | 33.69% |
| 1회 최대 | 80.8배 |

덩어리 적중률은 배당이나 잭팟 비중을 바꿔도 33.7%로 그대로다. 배당액만 움직였고
덩어리가 생기는 확률은 건드리지 않았기 때문이다.

같은 배당표로 400만 스핀을 두 번 돌리면 0.2%p 정도 차이가 난다(추정량 차의 표준오차
√2 × 0.11 = 0.16%p). 단일 숫자를 확정값처럼 쓰되 이 오차 폭을 함께 기억한다.

**필수 적중 잭팟의 환수율은 거의 정확히 계산된다.** 적립분은 전액 되돌아오고 공짜로 얹히는 건
시드뿐이다. 등급 t의 기여는

```
P(그 주머니를 채우는 심볼 개수) x 한 번에 넣는 배수 x (시드 + 천장) / (천장 - 시드)
```

이다. 심볼 개수 확률만 실측이고 나머지는 해석적이다.

| 등급 | 심볼 | 확률 | 한 번에 | 기여 | 평균 주기(총 베팅 20만) | 평균 지급 |
|---|---|---|---|---|---|---|
| GRAND | 4개+ | 2.18% | 총 베팅의 70% | 2.29% | 7,868스핀 | 3,600만 (180배) |
| MAJOR | 3개 | 7.66% | 13% | 1.49% | 2,009스핀 | 600만 (30배) |
| MINOR | 2개 | 21.78% | 3.7% | 1.21% | 496스핀 | 120만 (6배) |
| MINI | 1개 | 37.92% | 1.8% | 1.02% | 146스핀 | 30만 (1.5배) |

네 등급 모두 천장 = 시드 x 5로 맞췄다. 그래서 마지막 항이 1.5로 딱 떨어지고,
`한 번에 넣는 배수` 하나만 건드리면 환수율과 주기가 같은 비율로 움직인다.

**배당도 역산으로 구했다.** 덩어리에서 당첨 성립 여부는 배당액을 보지 않으므로 캐스케이딩과 같이
**RTP가 배당에 대해 선형**이다. (심볼, 구간)별 계수를 한 번 실측한 뒤 목표값에 맞춰 풀고,
보기 좋은 값으로 스냅한 다음 그리디 패스로 마무리했다.

**스트립을 704칸으로 늘린 이유.** 처음 44칸으로 만들었을 때 심볼별 덩어리 빈도가 배열 순서에
크게 흔들렸다. 시드만 +505 바꿨는데 엽전 20.2% / 매듭 1.7%로 20배가 벌어졌다. 짧은 고정
스트립에서는 같은 심볼이 우연히 이웃한 자리에 몰리는지가 덩어리 성립을 좌우하기 때문이다.
가중치를 16배로 키워 704칸으로 만들자 그 편차가 평균되어 서로 다른 시드 3개에서 배당 사다리가
단조성을 유지했다.

### 용문 밸런스

가변 릴 + 캐스케이딩도 전수 열거가 불가능하다. 다만 심볼 제거 여부는 당첨 성립만 보고
배당액은 보지 않으므로 **RTP가 배당에 선형**이다. (심볼, 개수)별 계수를 한 번 실측하면
어떤 배당표의 RTP든 즉시 나온다. 솔버가 그 계수로 목표값을 풀고, 보기 좋은 값으로 스냅한 뒤
그리디 패스로 마무리한다. 세로(개수 사다리)와 가로(심볼 사다리) 단조성을 둘 다 강제한다.

```bash
node tools/gate-solve.mjs 1.05 1500000   # 계수 실측 + 배당표 역산
node tools/gate-sim.mjs 500000           # 게임이 쓰는 spinGate로 독립 검증
```

**확정값** (솔버 150만 스핀 105.00% / 독립 시뮬 50만 스핀 실측)

| 항목 | 값 |
|---|---|
| RTP | **105.99%** (표준오차 ±1.03%p, 95% 신뢰구간 103.96~108.02%) |
| 적중률 | 44.50% |
| 프리스핀 | 1/210스핀, 스핀당 0.050회 |
| 1회 최대 | 1,286배 |
| ways 분포 | <100 0.09% · 100+ 24.70% · 1k+ 70.85% · 10k+ 4.35% · 50k+ 0.01% |

솔버(105.00%)와 독립 시뮬(105.99%)이 1%p 어긋나는데, 시뮬의 95% 신뢰구간이 ±1.03%p라
분산 안이다. 솔버 쪽은 배당액을 쓰지 않고 계수를 세므로 같은 스핀 수에서 분산이 훨씬 작다.

**릴 높이 분포가 환수율을 지배한다.** 높이 가중치만 바꿔 재 보면
95.6% → 228.88%(완만한 분포) → 538.71%(높은 쪽에 몰린 분포)로 폭발한다.
ways는 높이의 곱이므로 6릴에서 평균 높이 1단 상승이 곱으로 6제곱된다.
그래서 낮은 높이가 흔한 보수적인 분포(22/26/22/15/10/5)를 고정하고 배당으로 맞췄다.

**배당 0을 허용하지 않는다.** 솔버의 값 격자를 `toFixed(2)`로 만들었을 때 0.001이 0으로
접혀 `rank10 {3: 0}`이 나왔다. 배당이 0인 심볼은 연속을 끊는 벽이 되어 규칙 자체가 달라진다.
`toFixed(4)` + `n > 0` 필터로 막았다.

### 화투 밸런스

**이 게임만 몬테카를로가 필요 없다.** 족보 판정이 심볼의 *개수*에만 의존하므로,
릴별 2칸 창의 분포를 개수 벡터로 접어 5릴을 합성하면 모든 족보의 확률이 오차 없이 나온다.
스톱 조합은 648⁵ = 114조지만, 10장을 13종에 나누는 개수 벡터는 C(22,12) = 646,646가지가
상한이라 그쪽으로 접는다(실제 도달 608,019가지). 확률 합이 `1.000000000000`으로
떨어지는 것이 검산이다.

```bash
node tools/hwatu-rtp.mjs        # 해석적 계산 (10초)
node tools/hwatu-solve.mjs 1.05 # 배당표 역산
node tools/hwatu-sim.mjs 3000000 # 게임이 쓰는 spinHwatu로 교차 검증
```

**확정값 (해석적, 오차 없음)**

| 항목 | 값 |
|---|---|
| 배당 몫 | 48.4527% |
| 고 계수 | **2.1654** |
| RTP | **104.9178%** |
| 적중률 | 47.4240% |
| 스핀당 표준편차 | 4.959배 (고 제외) |
| 이론 최대 | 602.7배 → 4고에서 **6,027배** (오광 + 고도리 + 열끗 5장) |

**고 배수도 정확히 계산된다.** 배수를 스핀에 *들어갈 때*의 단계로 곱하므로, 단계는
"당첨이면 +1, 꽝이면 0" 마르코프 사슬이고 정상분포가 닫힌 형태로 나온다. 적중률을 p라 하면

```
pi(k) = (1-p) p^k   (k < 상한),   pi(상한) = p^상한
고 계수 = sigma pi(k) x 배수(k)
```

이고, 스핀 결과가 과거와 독립이므로 `E[당첨 | 단계] = E[당첨]`이다. 따라서
`RTP = 배당 몫 x 고 계수`로 정확히 쪼개진다. 300만 스핀 교차검증에서 실측 고 분포가
52.607 / 24.949 / 11.831 / 5.579 / 5.034%로 나와 계산값 52.576 / 24.934 / 11.825 /
5.608 / 5.058%와 일치했다 — 마르코프 가정까지 확인된 셈이다.

**스트립을 648칸으로 늘린 이유.** 81칸에서는 가중치가 같은 홍단·청단·초단의 족보 확률이
5.92 / 6.84 / 6.53%로 **15.4%** 벌어졌다. 2칸 창으로 보기 때문에 같은 심볼이 우연히
이웃하는지가 족보 성립을 좌우한다. 가중치를 8배로 키워 648칸으로 만들자 편차가
6.42 / 6.53 / 6.53%(**1.8%**)로 줄었다. 세 족보에 같은 배당을 주려면 확률이 같아야 하고,
확률이 같으려면 스트립이 길어야 한다.

| 스트립 | 단 세 가지 확률 | 편차 |
|---|---|---|
| 81칸 | 5.922 / 6.836 / 6.534% | 15.4% |
| 162칸 | 6.975 / 6.381 / 6.230% | 12.0% |
| 324칸 | 6.606 / 6.456 / 6.680% | 3.5% |
| **648칸** | **6.416 / 6.533 / 6.530%** | **1.8%** |

**배당 바닥을 0.2배로 깔았다.** 자유롭게 풀면 가장 흔한 족보(피 6장, 8.55%)가 0.06배로
내려갔다. 이름 붙은 족보가 베팅의 6%를 주면 당첨이라 부르기 민망하다. 바닥을 올린 몫은
솔버가 위쪽에서 가져왔다(오광 600 → 사광 50 → 삼광 6배). 구간 사다리는 같은 값을 허용하지
않는다 — `피 7장 = 피 6장`이 되면 구간을 나눈 뜻이 없다.
